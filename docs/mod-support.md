# 读取模组地图：可行性报告

> 结论：**可行，而且比预想的简单**。真正的工作量不在"读"，而在把现在写死的几个假设改成动态的。

## 一、实测：本机装了 21 个模组，5 个带自己的地图

| 模组 | 省份数 | 地图尺寸 | 解析结果 | 耗时 |
|---|---|---|---|---|
| The road to 56 CN | 13,535 | 5632 × 2048 | 100% 匹配，0 未匹配颜色 | 2.3 s |
| Thousand Week Reich | 13,747 | 5632 × 2048 | 100% 匹配，0 未匹配 | 2.2 s |
| Old World Blues | **21,833** | **5632 × 2304** | 100% 匹配，0 未匹配 | 2.8 s |
| Kaiserredux 汉化 | 16,102 | — | 定义表 16,102 行，含完整 map/ | — |
| TNO Map Mod | — | — | 没有独立的 `map/provinces.bmp`，是叠加式补丁 | — |

测试方法：直接读模组目录里的 `map/definition.csv` + `map/provinces.bmp`，把 CSV 的颜色列建成字典，再把 BMP 的每个像素映射成省份号。

**关键结论：一个像素都没漏。** 说明这套数据和原版是同一种格式，不需要任何猜测。

## 三、现有程序必须改的四处

### 1. 调色板 LUT —— 已经不用改了（实测）

写报告时我以为它是写死的 `128 × 105 = 13,440`。查代码后发现实际是
`LUT_H = ceil(省份数 / 128)`，本来就跟着数据包走。

随后做了实测验证：

| 数据包 | 省份数 | LUT 高度 | 结果 |
|---|---|---|---|
| 原版 | 13,414 | 105 | 正常 |
| 千周之国 | 13,747 | 108 | 正常 |
| Old World Blues | **21,833** | **171** | **正常，包含 5632×2304 的非常规尺寸** |

所以这一条从"必须改"降级为"已满足"，真正的瓶颈只剩显存。

### 2. 地图尺寸常量（**必须改**）

代码里多处 `5632 × 2048` 的假设。OWB 是 `5632 × 2304`，高度不同。

- 显存：`5632 × 2304 × 2 字节 ≈ 26 MB`（省份索引纹理），可接受
- 如果哪个模组把宽度改到 8192，会到 38 MB 以上，低端核显要留意

### 3. 省份名其实不存在

翻遍原版 2,093 个本地化文件，**`PROV<编号>` 这种键一个都没有**。

HoI4 里地图上显示的地名，本质上是**胜利点城市名**（`VICTORY_POINTS_1785:0 "杭州"`）。所以：

- 我们的"1,492 个有名字的省份"其实就是"有胜利点的省份"
- 模组只要自带自己的胜利点，名字就能自动出来
- 没写名字的省份，可以退回显示编号或留空

### 4. 国家颜色语法不统一

实测四种写法都有：

```
color = { 102 51 153 }            ← 最常见
color = rgb { 102 51 153 }        ← 也常见
color = {
    102 51 153                     ← 跨行，TWR 66 个文件里 48 个是这种
}
color = hsv { 0.5 0.4 0.8 }       ← 少见，本机 0 例
```

现在的解析器只认第一种，必须放宽。

## 四、剧本（1936 / 1939）在模组里大概率没有

原版 1,081 个州文件里，只有 **195 个**写了带日期的历史（`1936.1.1 = { owner = ... }`）。
Thousand Week Reich 的 1,293 个州里，带日期历史的只有 **1 个**。

也就是说：**模组基本只有一个状态**（无日期的那份归属）。1939 剧本要么没有，要么得我们另外造。

可行做法：
- 有日期历史的州 → 按日期求值，生成多剧本
- 没有的 → 只出单剧本，开始页少一张卡

## 六、风险

1. **叠加式模组**（overlay）：像 TNO Map Mod 这种自己不画地图、只改别的文件的，需要按加载顺序合并文件系统。工作量会增加，但不难。
2. **汉化不全**：有些汉化模组只翻了界面没翻地名，会出现中英混排。可以按"中文 → 英文 → 编号"三级回退。
3. **极端尺寸**：万一遇到改宽度到 8192 的模组，老显卡可能撑不住，需要加"降采样渲染"的兜底。
4. **版权**：模组素材同样受版权保护，和原版一样，只能本地生成、不能随程序分发。

## 七、建议的推进顺序

**第一期（建议先做）**：写 `build_pack_from_game.py`，直接读原版游戏目录，不再需要「悖论制图」导出的中间包。这一步本身就有价值——现在别人拿到仓库，没有那个中间包根本跑不起来。

**第二期**：加 `--mod "模组目录"` 参数，按覆盖顺序合并文件，读模组自己的省份图 / 州 / 颜色。

**第三期**：图形管线动态化（LUT、宽高），用 OWB 这种 21,833 省的极端案例压测。

做完之后，工具的形态是：**每个模组一个 `.pdxmap`**，打开时选包就行——现在的 `?pack=` 参数和多包切换机制已经支持了。

## 八、一句话回答

能读。省份图和定义表是标准格式，实测三个模组零误差；真正要改的是我们这边写死的"13,414 个省、5632×2048"这些假设，以及名字和剧本这两个数据源的口径。
